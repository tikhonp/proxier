# Open questions

Decisions deliberately left open, and facts to verify during the build. When one is settled, move the answer into the relevant doc (and an ADR if it qualifies) and delete it here.

Settled on 2026-10-07:
- UI technology → templ + htmx ([ADR 0014](./adr/0014-server-rendered-ui-templ-htmx.md)).
- Proxy hostnames in certificate-transparency logs → an accepted risk for the first version, with central wildcard certificates planned ([servers module](./modules/servers.md#dns), [roadmap](./roadmap.md#later)).
- "Activate anyway" → yes ([provisioning](./processes/servers/server-provisioning.md#steps--after-a-failure)).
- Root or a deploy user → a `proxier` sudo user; root login is turned off ([provisioning](./processes/servers/server-provisioning.md)).
- Proxy test URL → configurable, globally and per template ([health](./processes/servers/server-health.md)).

Settled on 2026-10-09, while planning Phase 4:
- `mtvpn:` naming → kept: the infra-pin prefix, `to_vpn_list` and `vpn-doh` stay ([ADR 0010](./adr/0010-router-contract-stays-mtvpn-compatible.md)); a router with other names already works through its per-router names.
- Zero-touch router registration → built in Phase 4 ([4b](./build/4b.md)): a `@fill proxier-ssh-key` parameter is filled with Proxier's public key, so the imported script creates the `proxier` user and adds the key itself ([router scripts](./modules/router-scripts.md#parameters)).

## To verify during the build

1. **Client apps and the stub entry.** Which apps replace their list when a successful refresh returns one stub entry (expected: Happ, v2RayTun, Hiddify, Streisand, v2rayNG, Shadowrocket)? Which ones keep the old list on a `404`? This is the basis of [ADR 0004](./adr/0004-one-shared-credential-per-endpoint.md).
2. **Subscription headers** honoured per app: `profile-title`, `profile-update-interval`, `subscription-userinfo` (expire), `content-disposition` filename.
3. **check-host.net API**: ~~endpoints, response shapes and node names~~ (answered in 1f, 2026-10-08, against the real service: `/nodes/hosts`, `/check-tcp`, `/check-result/{id}`; shapes in [the integration doc](./integrations/check-host.md#api-as-observed); 3 Russian nodes, none in Finland). Still open: its rate limits and terms of use for automated use, which no page states; Proxier stays at 6 nodes per check, 30 min per server and 60 checks per hour, and a refusal shows as an HTTP error (`unavailable`).
4. **iplist custom export**: ~~whether `format=custom` can emit the domain itself (for the reverse index), beyond the `{group}|{site}` template mtvpn uses~~ (answered 2026-10-08 while planning Phase 3, against the live portals: the template's `{data}` placeholder prints the selected data, so `template={group}|{site}|{data}` gives one `group|site|domain` line per domain. The whole export was small that day: main 880 lines (228 sites, 20 groups), beta 4 540 (102 sites), russia 351 (87 sites). The catalog indexes every iplist domain ([3c](./build/3c.md)).)
5. **RouterOS**: ~~SFTP vs SCP upload on the target versions~~ (decided in Phase 3 planning and built in 3e: SFTP with a plain write, no temporary file or rename; mtvpn's `scp` on macOS speaks SFTP since OpenSSH 9.0, so the user's router already accepts it). Still to verify on the first real router: the exact commands the add page shows (`/user group add name=proxier policy=read,write,ftp,ssh`, `/user add name=proxier group=proxier`, `/user ssh-keys add user=proxier key="<key>"`), whether that group is enough for `/import` of the service blocks, and `/ip dns forwarders` in the check. Test connection's upload check and the import scan's "not enough permissions" catch a missing policy. Since Phase 4 the router script can run the same lines itself (zero-touch, [4c's exit demo](./build/4c.md#phase-4-exit-demo)), so they must also work from an imported script, with `[:rndstr …]` giving the user a password nobody knows.
6. **xray-core as a library**: ~~the binary size impact~~ (answered in 1c: v1.260327.0 embeds with `CGO_ENABLED=0`; the stripped binary grew from 47.3 to 62.4 MB, the image from 71 to 92.8 MB, and building it after adding xray took 17 s on the host with xray compiled from scratch and everything else cached; details in [1c](./build/1c.md#as-built)). Still open: the XHTTP `stream-up` client mode working through nginx `grpc_pass` exactly as the template's links expect. It is checked by the first provisioning on a real VPS, which 1d built the means for but could not do (no VPS here): **not answered yet**, the smoke test of the first real run answers it. The proxy test is proven against an in-process xray XHTTP server, which accepts any mode, so it says nothing about nginx. One more finding: xray's own XHTTP client has a data race (`splithttp.WaitReadCloser.Set`) that `go test -race` reports, so the packages that push XHTTP traffic (`proxy` and, since 1d, `provision`) are tested without `-race` ([Makefile](../Makefile)); tests elsewhere use `serverstest.StubProxy()`.
7. **tsnet with headscale**: whether the node joins headscale 0.29 with a pre-auth key, and whether it needs a non-expiring key. Built in 0e: the key is used only while the node has no login (the state in `/data/tailnet` keeps it across restarts), Settings → Integrations → Tailnet shows the key expiry and takes a new pre-auth key (never stored), and a node with saved state starts without `PROXIER_TS_AUTHKEY`. Not yet tried against the real headscale: join, restart, and what happens at expiry.
8. **Russian throttling of foreign hosting networks** (stalling after the first ~16–20 KB) as it applies to the chosen test payload size. 1f built the means to see it (the proxy test's `stalled` class, the blocked verdict with its reason); only a real server in a throttled network answers it.
9. **A reset router's first fetch** (Phase 4). `fresh-router.rsc` wants a configuration reset with `no-defaults=yes`, which leaves the router without internet, so `/tool fetch` needs a DHCP client on the WAN port first; the script then adds its own (`/ip dhcp-client add interface=$wanIface`), which RouterOS may refuse as a second client on the port and stop the import. To verify on the first real router, with `/tool fetch`'s user agent and how long the fetch, the import and the probe take: the Phase 4 exit demo ([4c](./build/4c.md#phase-4-exit-demo)) answers it. Until then the generation page's Fetch URL area says to give the WAN port a DHCP client first (built in 4c).
